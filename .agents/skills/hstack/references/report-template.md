## 8. 한계와 출시 판단

- 탐색적 테스트는 [시간 상자 또는 완료한 범위] 안에서만 진행했다.
- 이 실행으로 확인하지 않은 영역: [목록]
- 전체 판정 근거: [모든 in-scope 요구사항 통과 여부, 미해결 결함, 차단된 흐름을 근거로 작성]
- 결정적 테스트 결과와 실제 배포 브라우저 결과를 구분한다. 한쪽의 통과를 다른 쪽의 통과로 간주하지 않는다.
- 프로필이 없거나 오래된 경우, 미확인/미커버 기능과 프로필 신뢰도에 미치는 영향을 적는다.

탐색적 `PASS`는 기록한 단계와 시간 범위에서만 문제가 관찰되지 않았다는 뜻이다. 확인하지 않은 화면이나 상태까지 통과했다는 뜻으로 확대하지 않는다. 전체 판정은 아래 우선순위로 내린다. `Not ready`는 in-scope 요구사항 실패 또는 확인된 P0/P1 결함이 있을 때 우선한다. 그런 문제가 없더라도 요구사항 출처가 없거나 in-scope 시나리오가 차단·미실행이거나 필수 증거가 부족하면 `Inconclusive`다. 프로필 기반 QA에서는 in-scope 기능 중 live check가 차단·미실행인 기능이 있거나 in-scope 요구사항이 feature ID에 연결되지 않으면 `Inconclusive`다. 사용자 릴리스 범위 밖의 기능은 기능 커버리지 분모에서 제외하고 별도로 기록한다. 민감정보 때문에 PASS/FAIL 화면을 안전하게 캡처할 수 없으면 `none`과 사유, URL, 화면 크기를 기록하고 증거 부족 여부를 `Inconclusive`에 반영한다. 모든 요구사항이 증거와 함께 통과하고, 프로필 기반 QA라면 모든 in-scope mapped feature가 live check를 통과했으며, 차단·미실행·증거 누락이 없지만 P2/P3 결함이나 사용성 문제가 남으면 `Ready with issues`다. `Ready`는 모든 요구사항과 해당되는 기능 커버리지가 증거와 함께 완료되고, 탐색적 테스트 범위가 완료되며, 미해결 결함이 없을 때만 사용한다. 남은 결함과 사용자의 다음 조치를 함께 적는다.
